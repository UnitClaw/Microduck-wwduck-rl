# Microduck R17 V163 / control.40 构建与使用范围

当前中控为 `1.0.163`，固件为 `1fa8438-feetech-ft6-control.40`，目标系统为官方 `0.15.1` 的 Linux AArch64。完整操作见 [中控说明](console/README.zh-CN.md)，模型及标定见 [固件说明](packaging/README.zh-CN.md)。本文只描述当前交付。

## 实体 L3 滑轮起身测试

L3 是左摇杆按下。按键通过 padd 读取现有 `robot.mode`、`robot.health` 和 `robot.state`，确认滑轮模式、策略已启用、无正在执行的动作、IMU 已就绪且新鲜，倒地判定与实际四元数一致后，向已有 `robot.do` 接口请求 `roller_stand`。

测试使用零命令，缩放 1.0，头腿滤波 1.0，不连发；本地技能配置提供 5 秒窗口，结束后交回滑行模型，Start 可以取消。窗口是手动测试设置，原导出合同没有声明时长。直立、行走、HOME、卸力、反馈过期、模式已切换或模型未加载时，按键不发出起身请求并记录原因。此入口不启用策略、不自动上力；先前正常完成 HOME 并启用滑轮策略是执行条件。

robotd 的控制、串口、启动及 IPC 实现保持当前流程，源码仅更新 BUILD 标识。服务单元、标定、镜像修复、SSH 凭据与开源入口按已确认配置保留。网页 L3 保持禁用，只显示操作说明；LB 保留左脚踢球。

模型使用原始滑轮起身导出；ONNX SHA256 为 `2575b5894bcd8e3fdbe005b1a7b90d9491085726df32000c26cf5b92b7a10ebb`。归档名为 10000，manifest 实际检查点为 11000。合同、训练信息及权重逐文件保留。

## 工具与构建

已实际使用 Rust `1.99.0`、Zig `0.15.1`、cargo-zigbuild `0.23.4`，目标 `aarch64-unknown-linux-gnu.2.31`。构建需要 Rust AArch64 标准库、AArch64 libudev 开发文件、Linux 本机构建依赖、Python 3、readelf 和 ONNX Runtime。主机测试必须设置 `ORT_DYLIB_PATH` 为主机架构的 ONNX Runtime，不能使用包内 ARM64 库运行主机测试。

配置交叉编译所需的 `PKG_CONFIG_ALLOW_CROSS=1`、`PKG_CONFIG_SYSROOT_DIR` 及目标 `PKG_CONFIG_LIBDIR`；设置 `QEMU_AARCH64` 为 QEMU ARM64 程序路径，`ARM64_RUNTIME_PREFIX` 为兼容的 ARM64 运行根目录。然后在工程根目录运行：

```bash
bash build-V163.sh
```

脚本运行当前测试范围，编译真实 robotd/padd，以 QEMU 校验全部十个模型，再打包和验证成品。robotd 与 pet-detect 的 release codegen-units 为 1。第一个参数可指定基础 ZIP，第二个参数可指定输出 ZIP。

基础配置为 `base/Microduck-Console-R17-V162.zip`，固定 SHA256 `9e8d82ea6a57dfbfa15592fab980e57a1e67fb2dff1b6e7bfb63f773a2283a5e`。打包器拒绝旧程序、错误构建标识、未通过测试或不匹配的 ARM64 模型记录；成品验证通过实际中控固件导入接口，并逐文件核对变动范围。
